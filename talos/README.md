# Talos

Machine configs are generated by talhelper from `talconfig.yaml`. Secrets are in `talsecret.sops.yaml`. Run all commands from this directory, in the devshell, which sets `TALOSCONFIG`.

| Node | IP | Notes |
|---|---|---|
| master01 | 192.168.0.210 | Only control plane. API is down while it reboots. |
| worker01–03 | 192.168.0.211–213 | Hold the Longhorn replicas. |
| worker04 | 192.168.0.214 | GPU. NVIDIA driver version comes from the Talos version. |

`talosVersion` and `kubernetesVersion` in `talconfig.yaml` must match the cluster. Kubernetes is pinned, so a Talos upgrade does not change it.

`talhelper gencommand` prints `talosctl` commands. It doesn't run them.

## Reboots

Reboot one node at a time: master01, worker04, worker01, worker02, worker03. Before the next one, check that every node is Ready and every attached Longhorn volume is `healthy`. Detached volumes show `unknown`.

```
kubectl get nodes
kubectl -n longhorn-system get volumes.longhorn.io
```

Drain the node. Its pods move to other nodes either way: without a drain, the kubelet stops them at shutdown and they're recreated elsewhere, but their volumes stay stuck attaching until the node is back. A drain detaches them first.

Every volume has a replica on each of worker01–03, so rebooting one of them makes its replicas resync. Expect about 40 minutes per worker.

`talosctl reboot` gives up after 30 minutes and still exits 0. If a node doesn't answer ping within about 10 minutes, check its console.

Pods don't move back after a reboot. To even out placement, delete pods on the busiest node so their Deployments recreate them. Don't use `kubectl rollout restart`: with a ReadWriteOnce volume, the new pod can't attach it until the old pod stops, so the rollout stalls.

To avoid resyncs, suspend Flux and scale every workload that uses a Longhorn volume to 0. Detached volumes don't resync. Scale back up a few namespaces at a time. Starting everything at once overloads the worker disks and causes replica timeouts.

## Apply config

```
talhelper genconfig
talhelper gencommand apply --extra-flags=--dry-run
```

Check each node's dry-run diff. Certificates, keys and tokens must not change. The diff prints private keys, so don't paste it anywhere.

If no node needs a reboot, apply:

```
talhelper gencommand apply
```

If the dry run reports a reboot, a dry run with `--extra-flags=--mode=no-reboot` lists the fields that need it. Stage the config, then reboot each node as described in [Reboots](#reboots):

```
talhelper gencommand apply --extra-flags=--mode=staged
talosctl -n <ip> reboot --drain
```

## Talos upgrade

Go one minor version at a time, to the latest patch of each (e.g. 1.11 → 1.12.x → 1.13.x). The target version must support the running Kubernetes version.

1. Set `talosVersion` in `talconfig.yaml`.
2. Take an etcd snapshot and keep it outside the repo:
   ```
   talosctl -n 192.168.0.210 etcd snapshot ~/etcd.snapshot
   ```
3. Upgrade each node as described in [Reboots](#reboots). Print the commands with:
   ```
   talhelper gencommand upgrade
   ```
4. Apply config so the nodes have the new install image.

## Kubernetes upgrade

Go one minor version at a time. The running Talos version must support the target.

1. Set `kubernetesVersion` in `talconfig.yaml`.
2. Dry run, then run for real:
   ```
   talhelper genconfig
   talhelper gencommand upgrade-k8s --extra-flags=--dry-run
   talhelper gencommand upgrade-k8s
   ```
3. Run the [apply config](#apply-config) dry run. It should show no Kubernetes image changes.
