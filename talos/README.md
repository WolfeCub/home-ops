# Talos

Machine configs are generated by talhelper from `talconfig.yaml`. Secrets are in `talsecret.sops.yaml`. Run all commands from this directory.

| Node | IP | Notes |
|---|---|---|
| master01 | 192.168.0.210 | Only control plane. API is down while it reboots. |
| worker01–03 | 192.168.0.211–213 | Hold the Longhorn replicas. |
| worker04 | 192.168.0.214 | GPU. NVIDIA driver version comes from the Talos version. |

`talosVersion` and `kubernetesVersion` in `talconfig.yaml` must match the cluster. Kubernetes is pinned, so a Talos upgrade does not change it.

`talhelper gencommand` prints `talosctl` commands. Run them one node at a time.

## Apply config

```
talhelper genconfig
talhelper gencommand apply --extra-flags=--dry-run
talhelper gencommand apply
```

Check each node's dry-run diff before applying. Certificates, keys and tokens must not change. The diff prints private keys, so don't paste it anywhere.

If the dry run reports a reboot, apply one node at a time and follow the Longhorn rules below, or add `--mode=staged` to apply at the next reboot.

## Talos upgrade

Go one minor version at a time, to the latest patch of each (e.g. 1.11 → 1.12.x → 1.13.x). The target version must support the running Kubernetes version.

1. Set `talosVersion` in `talconfig.yaml`.
2. Take an etcd snapshot and keep it outside the repo:
   ```
   talosctl --talosconfig=./clusterconfig/talosconfig -n 192.168.0.210 etcd snapshot ~/etcd.snapshot
   ```
3. Print the upgrade commands with `talhelper gencommand upgrade`.
4. Upgrade one node at a time: master01, worker04, worker01, worker02, worker03. Wait for each node to be Ready.
5. Before rebooting each of worker01–03, check that all Longhorn volumes are Healthy. Replicas on a rebooted node resync after it comes back.
6. Apply config so the nodes have the new install image.

To skip the resyncs, suspend Flux and scale every workload that uses a Longhorn volume to 0 before step 4. Detached volumes do not resync. Scale back up a few namespaces at a time. Starting everything at once overloads the worker disks and causes replica timeouts.

## Kubernetes upgrade

Go one minor version at a time. The running Talos version must support the target.

1. Dry run, then run for real:
   ```
   talosctl --talosconfig=./clusterconfig/talosconfig -n 192.168.0.210 upgrade-k8s --to <version> --dry-run
   talosctl --talosconfig=./clusterconfig/talosconfig -n 192.168.0.210 upgrade-k8s --to <version>
   ```
2. Set `kubernetesVersion` in `talconfig.yaml`, then apply config. The dry run should show no Kubernetes image changes.
